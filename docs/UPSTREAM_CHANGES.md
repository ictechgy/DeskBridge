Knot changes, 2026-10-18:

- NEW Protocol/StreamSecurityPolicy.swift: require encrypted rtspenc signalling and all three media/control capability bits.
- Network/RtspClient.swift: apply pure mandatory policy in the real pre-network/RTSP negotiation path.
- Network/RtspClient.swift (preview.8): authenticate encrypted responses, reject repeated/older host sequence numbers independent of the outbound counter, and bind exactly one CSeq to the request before committing receive state. Strict monotonic ordering permits gaps from retries and rejects wrap within the instance; complete headers/status are required. No plaintext fallback or destination change is introduced.
- Network/InputBatcher.swift (preview.9): report actual report/pair send acceptance; preserve unsent mouse chunks, absolute positions and reliable gyro-null state; refuse later ordering barriers and mouse mode/channel changes until earlier retained state drains. Only accepted relative chunks are consumed. Rejected state rearms one timer; terminal stop prevents replay. Superseded unreliable sensor samples remain droppable.
- Session/StreamConnection+Configuration.swift and Session/StreamSession+Connect.swift: request all-channel encryption.
- Input/StreamInput.swift: desktop input sequencing state.
- NEW Input/StreamInput+Desktop.swift: narrow public keyboard, committed text, absolute pointer and focus-release bridge.
- NEW Input/DesktopInputWire.swift plus Input/InputText.swift, Network/InputBatcher.swift, Session/NativeBackend.swift and Session/NativeBackend+Input.swift: desktop-only shared reliable channel, real text acceptance and a single-batch retry cursor so a remote save/click cannot overtake or duplicate pending text. Legacy non-desktop channel defaults are retained.
- Input/StreamInput+Desktop.swift (preview.8): once committed-text ordering allows a key event to replay, a new owned key release is recorded before older rejected releases are retried. Revoking focus/ownership still discards delayed text and queued key-down work. The reliable retry/reconciliation path remains authoritative for a rejected key release.
- Network/InputBatcher.swift and Session/NativeBackend+Input.swift: merge absolute pointer motion under backpressure while preserving the shared reliable channel and text/key/button barriers.
- Network/Network.swift, Pairing.swift, NetworkClient+Endpoints.swift, NetworkClient+Request.swift and ControlTransport.swift: provisional pairing trust, strict present session-key fields and HTTP framing, mandatory TLS pin, bounded exchange lifecycle and launch/resume reply ownership.
- Protocol/StreamCrypto.swift and Network/EnetControlChannel.swift / +Inbound.swift / +Send.swift: reject repeated or expired authenticated host counters before ENet receive-cursor admission, using one fixed 8 KiB replay bitmap per control session across all channels. The 65,536-counter window permits bounded out-of-order delivery; only successful GCM authentication commits it. Retransmissions remain ACKed, receive counters never wrap, and both outbound send modes fail explicitly before nonce-counter exhaustion. ENet channel, sequence and ACK fields remain unauthenticated transport metadata; this change does not authenticate them.
- Session/StreamSession+Public.swift: a public native lifecycle adapter connects the existing balanced activity and wake edges to Knot's platform implementation.

Credential storage hardening, 2026-10-23:

- Network/Identity.swift: file-backed identity storage opens the app base, Glimmer and Identity directories by descriptor and refuses foreign ownership, non-private modes, symlinks, non-ordinary files, hard links and every Darwin extended ACL. PEM reads are bounded to 64 KiB and unique IDs to 4096 bytes. Replacement validates a fresh exclusive mode-0600 temporary descriptor before writing secret bytes, then fsyncs and renames relative to the verified directory. Existing unsafe material is neither tightened nor removed.
- Network/Identity+Loading.swift: preflight every existing identity component before migration or generation and preserve a complete file-backed identity even without a version flag. Once the file-storage flag is published, certificate, key and unique ID must all remain present; loss of one or every component fails closed without generating replacements or changing recovery defaults. An unflagged legacy PEM pair may complete its unpublished migration with a new unique ID. Successful file recovery also removes legacy plaintext defaults and advances the storage flag. Only an uninitialized, genuinely absent identity permits fresh key creation.
- Network/Identity.swift and +Loading.swift: first publication stages all three components in an exclusive private generation, syncs and validates them, then publishes the complete identity with one directory rename. Existing partial or nonempty stores are refused. Process interruption leaves either no canonical identity or the complete identity; private orphan stages are ignored. A failure syncing the parent after publication preserves the complete canonical store for the next load.
- The native Core settings and SSH generation paths independently apply the same private-directory, ordinary-file and ACL policy. scripts/check_private_storage.py exercises the production store and loader through source extraction with synthetic defaults and crypto, and checks inherited ACL rejection before writes and key generation. Every fixture and generated test key is newly created under /private/tmp; existing preferences, credentials and device state are not accessed.

Control and lifecycle robustness, 2026-10-23:

- Network/EnetControlChannel+Inbound.swift: authenticate and admit reliable envelopes before acknowledging them. Exact accepted retransmissions are recognized by a bounded SHA256 fingerprint history with constant-time ring eviction; rejected or relabelled replay packets receive no ACK. ACKs precede command callbacks that may close the channel. Outer transport labels remain unauthenticated.
- Network/EnetControlChannel.swift and +ControlLoop.swift / +Inbound.swift: the first authenticated non-`-1` PC termination can supersede a dead-peer `-1` notification exactly once. The upgrade is marked only after successful encrypted reliable admission; local or rejected packets cannot upgrade it, and the first non-`-1` code is retained. Malformed authenticated termination payloads and an explicit `-1` retain the upstream link-loss sentinel semantics. Callback delivery remains outside the channel state lock and current-transport retirement still fences stale sources. Undelivered or reliably held messages are not force-dispatched after transport death.
- Network/ControlTransport.swift: scan only newly received header bytes plus the separator overlap, enforce a separate 64 KiB header ceiling, and retain the 4 MiB response/body bound. This bounds work for fragmented or incomplete headers.
- Network/RtspClient.swift: retry only pre-ready connection failures. Send/receive failures after TCP readiness retain their original failure and cannot replay a request the host may have processed.
- Network/RtpAudioReceiver.swift and extensions: validate encrypted data padding before queue admission while preserving ciphertext for FEC, retry receive resource pressure with bounded backoff, and report terminal audio receive failures without stopping video. CBC remains unauthenticated and retains the upstream sequence-derived IV limitation.
- Network/VideoRtpReceiver.swift and Session/NativeBackend+Pipeline.swift: drain the old video receive queue before cleaning the reused sink, reject stopped-receiver submissions, and deliver terminal callbacks outside that queue to avoid self-join deadlocks.
- Session/StreamSession+Public.swift: let the shell refresh the existing balanced presentation activity after actual visibility changes. Hidden/minimized presentation suppression also updates the existing power policy; this does not create a new capture or permission capability.
- Session/StreamSession.swift and +Reconnect.swift: retain a fatal event for its current replacement attempt and recheck success after the final asynchronous work. Quiesce input before retiring failed callbacks, classify host termination before another launch, and honor a confirmed PC-side app closure. Transient failures continue within the original recovery budget without reporting a successful reconnect; stale backend events remain excluded and native transport cleanup still drains before replacement. A separate current-transport observation retains PC termination before actor dispatch through retry backoff and route refresh; local dead-peer failure cannot suppress a PC code already admitted by the current transport's bridge. Explicit retirement closes observation atomically after input quiescence, immediately before synchronous transport stop, and preserves already accepted intent before replacement selection. A live PC trigger is classified before recovery is announced while failed decoder callbacks are already fenced. Later attempts replace an earlier retryable diagnosis when they have their own classified failure, while consequences from the same failed attempt preserve its first explicit error.
- Session/StreamSession+Reconnect.swift: a driver cancelled before the first recovery announcement still takes the shared ownership cleanup and terminal path. A stop during the initial PC-intent probe also releases episode ownership. Surviving recovery publishes reconnecting before clearing the waiting state; a confirmed PC close never briefly publishes live. Self-initiated recovery fences the old decoder epoch before suspension while keeping transport-termination observation active, and a later host failure does not rotate that already-fenced media epoch twice.
- Session/StreamSession.swift and +Wake.swift: each wake probe owns a generation token and captures its armed transport attempt. Actor consumption rejects cancelled or superseded probes before clearing the stored task, and rejects a changed attempt before reading current backend health; teardown invalidates the token before cancellation. A late old probe cannot erase a replacement's handle or act on a newer connection. The bounded current probe alone owns its wake verdict.
- Session/StreamSession+Lifecycle.swift: terminal stop clears the internal waiting flag without publishing a nonterminal waiting update. This prevents an old frame from promoting the shell to live during teardown, including a stop while the initial PC-intent probe is suspended. Ordinary hold and recovery waiting events retain their normal behavior.

Launch cancellation and parser limits, 2026-10-23:

- Session/StreamSession+Start.swift: consume takeover consent immediately after a successful launch, before the next actor hop or attempt check; a failed launch retains consent for retry. Clear the shared initial-launch request deadline on success, failure and cancellation before checking the next startup attempt. The paired NetworkClient can subsequently refresh the PC with its normal per-request budget.
- Session/StreamSession+Lifecycle.swift: disconnect-only stop cancels the inner pending launch task as well as its outer waiter; the owned-host cancellation disposition retains its bounded late-success cleanup. This does not authorize a disconnect-only session to send host `/cancel`.
- Session/NativeBackend.swift and StreamSession+Connect.swift: classify mandatory stream-encryption policy failures as typed security errors and preserve typed backend errors through reconnect cleanup, so shell guidance can name encryption, blocked ports or timeouts.
- Network/Network+Support.swift: bound XML input to 4 MiB, nesting to 64 elements, node count to 16,384 and retained character/CDATA text to 4 MiB. Budget exhaustion aborts parsing and rejects the response; it does not relax TLS pins or introduce a plaintext fallback.

- Video/VideoDecoder+Suppression.swift, +Decode.swift and VideoDecoder.swift: a compressed hidden-backlog drop gates further decode until resume without requesting a hidden-window wire IDR. The resync obligation clears only after an IDR reserves a decode slot; a second gate check after reservation prevents a racing visibility or decoder error from feeding an ineligible frame.
- Video/VideoDecoder+Decode.swift: if a visibility gate refuses an IDR already reserved for stall recovery, retire the wedged session on the serial decode queue before any resumed IDR can decode. The gate still drops the hidden IDR quietly and releases its reservation; gate lift cannot cancel the mandatory session replacement.
- Session/StreamSession+FrameWatchdog.swift and +Start.swift: reread decoder identity, watchdog arm and progress before consuming a queued timeout. Bound a visible, ungated decoder-reconnect attempt that keeps receiving packets without decoded output; a paused encoder retains its normal hold. Reset prior live-session state for a new startup.
