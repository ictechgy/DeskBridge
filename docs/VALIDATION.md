# Validation and device acceptance

## Reverse Windows-to-Mac desktop

The reverse feature has a separate acceptance scope from the existing Glimmer client. Agent checks compile its actual native Mac host adapter and Windows client code, exercise only new inert process groups, private temporary storage, DNS packets, generated QR/pixel fixtures and pure policy/command code. The exact pinned QR source is compiled offline; source/decoder/runtime inventories bind the Windows executable and required check record. A cross-platform core decoder pass or Windows GDI+ fixture compile is not a Windows image-codec runtime pass.

The packaged managed-payload checker calls the actual QR luminance adapter after the production embedded loader initializes, with no decoder DLL beside the helper. A fresh valid QR and blank rejection exercise dependency binding, and identity/idempotence checks constrain the resolver. The Framework-targeted Windows image fixture also uses a separately compiled embedded decoder; its compile-only result on Mac does not attest Windows execution. Synthetic Mac download checks cover receive-time byte bounds, redirect rejection before follow, timeout and cancellation without contacting an endpoint. The reverse interop fixture also exports the actual Swift host invitation through its Mac PNG producer, then feeds those fresh pixels through the packaged C# decoder and connection parser.

Actual Mac Sunshine capture, responsible-process TCC attribution to DeskBridge versus Sunshine, Screen/System Audio/Microphone purpose prompts and Accessibility, Windows engine/Job/ACL/DPI, encrypted negotiation with real devices, Korean IME/Command/system keys, audio, display input changes/EDID, lock/login/FileVault, sleep/wake and real LAN/Tailscale performance remain target-device acceptance. Agents do not launch production hosts/clients or inspect the current desktop to perform them. Previous Claude/Grok or source-review verdicts do not automatically approve this new direction. Reverse files and automatic clipboard synchronization are not part of this feature.

## Agent-run scope

- Real native app, GlimmerEngine and DeskBridgeCore compiled with direct Swift compiler and no dependency downloads.
- Actual binary/Info.plist/library dependency/ad-hoc signature checks.
- The offline checker uses the same static private dependency linkage and hardened-runtime ad-hoc signing policy as the app. Successful execution proves this loader policy; the GUI is not launched. Earlier failed dynamic-library loading evidence is retained.
- In-memory SFTP peers exercise codec/session/transfer code. Separate anonymous-pipe fixtures exercise the shared production packet framer, fragmented header/payload, malformed lengths/EOF, bounded deadlines and cancellation; no sockets or SSH process.
- Pure endpoint/settings/encryption policy checks.
- Complete production-engine RTSP decode checks use fresh host-originated AES-GCM fixtures: authenticated duplicate/older/wrapped sequence rejection, allowed independent-host gaps, wrong/missing/duplicate/malformed CSeq, short/truncated/excess frames, tampered sequence/tag, no plaintext fallback and no trusted-state consumption after failure. They call the same decoder as the runtime transaction without creating a socket or starting a handshake.
- Complete production desktop-input fixtures cover backpressured held-key releases behind pending text, release retry/order/deduplication and discarded delayed input after focus loss/stop. They use a fresh inert backend rather than a Windows session.
- SSH diagnostics use fresh byte/pipe fixtures to check bounded draining/classification and fixed messages, with no SSH process or raw user logs. Setup suggestion fixtures check deduplication, the eight-address bound, omitted counts and automatic APIPA exclusion while preserving the manual endpoint exception.
- The builder also runs isolated Python regression cases for source-file addition/deletion/change, brand-asset additions, app content/mode replacement, invalid/failed/skipped build evidence, symlinks, debug-release rejection and actual source-archive correspondence, including pre-build ignored/staged/untracked inputs, required root files, cache-named compiler/ancestor directories, direct generated cache acceptance, sourceless tooling bytecode and export attributes. Fixture Git routing/configuration/ignore/attributes are isolated, including a reference-transaction hook sentinel and a controlled positive check; archive failures retain their Git diagnostic. No real app is packaged by these tests.
- Settings checks inject a real filesystem save failure in a new temporary fixture; the publishable address and host stay at their prior values. Successful updates are persisted before publication.
- Independent review evidence is recorded per immutable source snapshot. Only a terminal verdict without authentication/tool/timeout errors counts as a completed review; earlier snapshots do not approve new changes. Check the final review records separately from build success.
- The final build/check record and exact counts are in evidence/latest-build.json and its synthetic-checks.stdout.

Official SwiftPM execution is blocked by nested sandbox in this agent environment. The direct compiler path does not turn off the inherited guard. Existing SDK macro warning is recorded; no GUI is launched and no existing preferences/Keychain/clipboard/screens or Windows files are used by checks.

## Windows11 Home + actual Mac acceptance (pending)

1. Sunshine installed and Desktop configured. LAN/WAN encryption Mandatory. Both LAN and Tailscale routes pair using approved PIN/certificate.
2. Incorrect PIN, changed host certificate, revoked pairing and plaintext/unsupported signalling fail closed with useful errors.
3. Switch physical monitor input to Mac. Confirm Windows still supplies expected capture resolution; test a locked session separately.
4. Open native fullscreen Space; Control-Up/Left/Right and trackpad Space switching work, with no stuck keys/mouse after focus changes.
5. Mac Korean IME: 한글 composition, backspace, cancellation, candidate placement, commit in VS Code and Windows Terminal; Windows IME in English.
6. Physical Windows mode: modifier, Cmd/Ctrl mapping, Ctrl-C/S/P/Q, arrows, function keys and local window/menu shortcuts.
7. Audio playback and output-device switch; display/refresh-rate switch; sleep/wake reconnect; user closes streaming window while connecting.
8. Fresh Windows OpenSSH setup script review/apply. Dedicated user is not administrator, has no shell/forwarding, cannot escape jail by traversal/symlink/junction.
9. Verify server Ed25519 key fingerprint out of band. Mismatched pin and wrong client key reject.
10. Upload/download Korean/space/bracket names, zero-byte and large files; compare SHA256 hashes. Existing destination is untouched.
11. Cancel during write/read, connection loss, disk full and permissions denied. No completed file is shown until successful finalization.
12. Disable helper revokes new access and handles established SSH sessions. Existing SSH installations require manual setup, never silent takeover.
13. Same Windows host/Wi-Fi/resolution/bitrate workload vs Chrome Remote Desktop: text legibility, input-to-present latency, throughput, CPU/GPU, frame drops. Record measurement method and timestamps.

All items above remain pending until executed on hardware. Source review or synthetic tests do not satisfy them.
