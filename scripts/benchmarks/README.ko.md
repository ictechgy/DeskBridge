# DeskBridge 벤치마크

현재 앱을 바꾸기 전에 기준선을 측정하는 도구입니다. `contract.json`이 측정 범위와 판정 조건입니다. 합성 결과를 Moonlight/Cyberduck/Chrome 원격 데스크톱보다 빠르다는 근거로 사용하지 않습니다.

## Mac에서 바로 실행

저장소 루트에서 Xcode/Swift 6 도구로 실행합니다. 결과 경로는 새 폴더여야 합니다.

```sh
python3 scripts/benchmarks/run.py --output /tmp/deskbridge-benchmark-result --repetitions 5
```

실제 production SFTPClient와 Glimmer 입력 소스를 `-O`로 컴파일합니다. 앱을 실행하거나 사용자 설정·파일·키·클립보드·화면·서비스 로그를 읽지 않습니다. 새 `/tmp/deskbridge-benchmark-*` 안에만 합성 파일·실행 파일·모듈 캐시를 만들고 종료 시 제거합니다. 보고서 폴더는 보존합니다. `--suite sftp` 또는 `--suite input`으로 나눌 수 있습니다.

`provenance.json`에는 소스 HEAD, 작업 상태, 컴파일한 파일 해시, 도구 버전, 실행 인자, 종료 코드가 남습니다. `sftp.json`/`input.json`은 원시 표본, `summary.json`은 요약입니다. **사용 가능한 결과는 provenance가 COMPLETE_SYNTHETIC_ONLY이고 결과 해시가 일치하며 RUNNING/FAILED 표시가 없는 실행뿐입니다.** 실패한 실행의 원시 JSON은 진단 자료입니다. 명령 타임아웃도 부분 출력과 종료124를 보존합니다. 실행 크기·지연·프로필·warmup이 contract와 다르거나 실행 중 소스가 바뀌면 검증이 실패합니다. HEAD와 함께 working tree의 실제 복사된 바이트·tracked diff/tooling patch 해시를 기록하므로 수정 중인 후보도 측정할 수 있습니다. 내부 재현용 provenance의 절대 경로에는 로컬 사용자/폴더 이름이 포함될 수 있습니다. 공개 보고서는 경로 없는 요약을 사용합니다.

- SFTP: 1/8MiB 업로드·다운로드, 응답당 인위적 지연 0/5/30ms, 기본 5회. 전체 전송 호출의 로컬 파일 IO·경로 검사·마무리를 포함하며 연결·데이터 생성·사후 해시는 제외합니다. 원격 상대는 메모리입니다. 실제 SSH 암호화·파이프·서버 디스크·회선 대역폭·동영상 간섭을 재현하지 않습니다. 고정 지연은 실측 RTT가 아니며, 타이머 지연을 포함한 실제 평균 응답 대기도 기록합니다. SHA-256·내용 일치·진행률·무덮어쓰기를 확인합니다. 취소 검사는 READ receive가 응답을 무기한 보류한 상태와 존재하는 부분 파일을 직접 확인한 뒤 취소하며, 독립 watchdog의 2초 상한 안에 완료되고 부분 파일이 제거되어야 통과합니다.
- 입력: 실제 backend/batcher/sender에 합성 keyboard/motion 패킷을 넣고 메모리 peer가 수락하는 시각을 잽니다. OS 입력·IME·ENet·암호화·Windows·디코드·디스플레이는 제외합니다. 기본 스레드 QoS를 사용하고 실시간 정책 설정 hook은 실행하지 않습니다. 진단/타이밍 tracker는 inert fixture입니다. 측정용 잠금/사전/시계 비용이 포함됩니다. 움직임은 병합되므로 수락 패킷의 최신 이벤트/가장 오래 대기한 이벤트 시간을 별도 기록합니다. 마지막 ordering barrier 1개가 표본에 포함됩니다. 수락 순서를 기록해 barrier가 정확히 한 번, 최종 motion 뒤, 맨 마지막에 수락되었는지도 검증합니다. 스케줄링 지연도 함께 보고합니다.

전송 5회의 median/min/max를 보고하고 p95/p99를 만들지 않습니다. 입력의 p95는 한 실행의 수락 패킷 100개 이상일 때만 표시합니다. 여러 실행을 독립적인 큰 표본인 것처럼 합치지 않습니다. 유휴 전력·보안 우열·전체 입력→화면 지연은 이 도구의 측정 대상이 아닙니다.

요약 JSON/표준 출력에도 각 suite의 제외 범위가 포함됩니다. 입력은 혼잡/역압이 없는 메모리 채널이고 NativeBackend의 저장 상태는 inert fixture이며 실제 입력 extension/batcher/sender를 측정합니다. 프로필 주파수는 목표 격자입니다. 실제 제출 간격 중앙값/p95와 목표 간격의20%를 넘는 지각 표시를 함께 보고하며 느리거나 병합된 표본을 버리지 않습니다. SFTP의 nominal+10ms 초과 로컬 타이머 지연도 표시하되 표본을 탈락시키거나 실제 RTT로 간주하지 않습니다. 무덮어쓰기 검사는 로컬 다운로드 목적지 보존만 직접 확인하며, 원격 업로드의 충돌/rename 경합은 미실행입니다. COMPLETE는 실행·계약 검증 완료이며 소스 승인이나 다른 HEAD가 기존 기준선과 동등하다는 뜻이 아닙니다.

입력은 keyboard와 motion을 각각 준비 실행합니다. motion1000Hz에는 재현 가능한 ±150µs 이벤트 jitter와 실행별 시작 offset을 넣습니다. `phaseOffsetNs`는 생산자 시작 시각을 옮기는 값이며 flush와의 위상을 무작위화한다는 보장은 아닙니다. 로컬 타이머와 생산자 위상에 따라 분포가 달라지므로 최신 이벤트/최장 대기 양쪽의 원시 분포와 실행별 통계를 확인합니다. 약1ms라는 대표값을 고정 보장으로 표현하지 않습니다. READ 취소 검사의 부분 파일은 첫 데이터 응답 전에 생성된 빈 파일이며, 데이터가 쓰인 후의 취소나 실제 SSH 프로세스 종료 지연은 측정하지 않습니다. 응답 지연 peer는 대역폭 제한·순서 역전이 없어 **파이프라이닝 전후 속도 비교에는 아직 사용할 수 없습니다.** 그 실험 전에는 실제 지연 보정·링크 직렬화/대역폭·응답 순서 교란 조건을 추가해야 합니다. 현 상태는 직렬 전송의 지연 민감도 진단용입니다.

## Windows 실기용 합성 자료

`New-BenchmarkFixture.ps1`과 `synthetic-desktop.html`을 같은 폴더에 두고 일반 PowerShell에서 실행합니다. 관리자 권한이나 정책 변경은 필요하지 않습니다. 조직 정책이 스크립트를 거부하면 변경하지 않고 그 상태를 기록합니다.

```powershell
.\New-BenchmarkFixture.ps1
# 선택: 큰 파일 크기 1–1024MiB
.\New-BenchmarkFixture.ps1 -LargeFileMiB 1024
```

새 임시 폴더에 랜덤 1MiB/100MiB 파일과 SHA-256 manifest, 합성 업무 HTML만 생성합니다. 기존 파일·네트워크·서비스·레지스트리·SSH 설정에 접근하지 않습니다. 아직 Windows에서 실행 검증하지 않은 생성기입니다. 테스트 뒤 출력된 해당 폴더만 삭제합니다. HTML은 외부 의존성·네트워크·영속 저장·클립보드 API가 없으며 키 내용을 기록하지 않습니다. 카운터는 호스트 이벤트 수일 뿐 원격 지연/FPS가 아닙니다.

생성 경로는 작업 시작 때 출력하고, 파일/HTML의 크기와 SHA-256을 manifest 배열에 넣습니다. 생성 중 실패하면 새로 만든 해당 폴더만 정리를 시도하고 원래 오류를 다시 던집니다. 정리가 실패하면 출력된 경로로 남은 폴더를 확인할 수 있습니다.

실기 비교는 같은 Windows Sunshine에 DeskBridge/Moonlight를 순차 연결하고 같은 OpenSSH 계정/새 격리 합성 폴더에 DeskBridge/Cyberduck을 비교합니다. 실제 버전·GPU/드라이버·해상도/배율·주사율·실제 코덱/크로마/비트레이트·관측된 경로를 기록합니다. Tailscale 100.x 주소만으로 direct라 판정하지 않으며 확인 불가능한 값은 UNKNOWN입니다. SSH 접속을 위해 기존 개인키/비밀번호를 보고서에 넣지 않습니다.

특히 같은 물리 모니터의 입력을 Mac으로 바꿨을 때 Windows 캡처 유지, 한글 조합/삭제, modifier 고착, Control+방향키 Space 전환, 재접속, 파일+화면 동시 사용을 확인합니다. 이 도구는 시스템 키를 자동 입력하지 않습니다. 화면 비교 수치는 외부 계측/검증된 별도 하네스가 필요합니다. 네트워크/서비스 장애 주입은 격리된 테스트 호스트에서만 수행합니다.

기준선이 단일 미결 SFTP 요청의 지연 병목을 보이면 제한형 파이프라이닝의 실험 근거가 됩니다. 제품 기본값 변경 전에는 응답 ID/순서·취소·메모리 상한·무덮어쓰기와 실제 OpenSSH 대조·영상 공정성을 추가 검증해야 합니다. 4:4:4·파일 큐·Tailscale 가져오기 등 다른 개선도 각 실기 증거를 확보한 뒤 우선순위를 정합니다.
