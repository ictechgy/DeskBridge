# Windows file transfer setup

For normal use, double-click the single Windows **quick-setup EXE** described in [INSTALLATION.md](../../INSTALLATION.md). No ZIP extraction or shell command is required. Its screen-first window guides Sunshine install → initial configuration → Mac PIN pairing; JSON/SSH setup is not required for desktop access. The optional **파일 전송도 설정하기** section imports the Mac's public setup JSON, requests UAC only for file configuration/revocation, and exports a public connection JSON. Compare the SSH host fingerprint on both screens before accepting it. The commands below remain available for manual integration and auditing.

Open the setup window normally as the desktop user who will use the shared files. An elevated setup window refuses to proceed and explains how to reopen it; a local administrator's normal filtered token is supported. The wizard captures that user's SID before its separate UAC prompt, including when another administrator supplies the elevation credentials.

For screens, the Mac searches Sunshine's Bonjour announcements on the local network. Windows **연결 QR / 링크 보기** generates an offline address-only QR and copyable link; neither includes secrets or authorizes a session. The Mac previews name/address before its normal PIN/certificate flow. Tailscale is not enumerated through multicast discovery; use QR/link or manual IP. Camera use is an explicit Mac action.

The quick-setup EXE includes the pinned MIT QR assembly and both upstream copyright notices. A raw developer folder without that assembly labels the action **연결 링크 보기** and offers a link only; load/generation failures of a present assembly still surface as errors. Portable packages made with `--windows-launcher` include it. No QR website or runtime package download is used.

In preview.8 the public EXE is a native x64 bootstrap. Before CLR starts, it limits DLL search, verifies the embedded managed helper, protects its fresh staging directory and starts the helper with a fixed working directory. Elevated children receive an OS-derived environment allowlist; the normal UI receives a token-derived user environment with CLR/profiling hooks and module/temp/system overrides removed. Child TEMP/TMP use stable OS-derived temporary locations, not the disposable payload stage. The original EXE is the primary UAC broker: it re-extracts its own backend scripts into protected Program Files and accepts only bounded known operations/public request fields. Sunshine's MSI is copied into that administrator stage and checked again against the embedded size/SHA256 pin before installation. A raw source-folder GUI uses a separately warned manual-script path; it does not provide the same primary EXE broker boundary.

Scripts remain unchanged exact-source bytes and are unsigned. An optional Authenticode signature on the outer helper/installer does not sign each PowerShell file. Organizations forcing AllSigned need separately signed scripts and an approved manual deployment. The process requests RemoteSigned only for itself; no permanent policy change or Bypass is used. Actual Windows loader/UAC/ACL/install acceptance is still pending.

This is a separate Windows OpenSSH SFTP endpoint. It does not run in Sunshine and it never uses Sunshine's service identity or pairing credentials. Windows 11 Home can install the OpenSSH Server optional feature. No public relay, cloud account or router port forwarding is used.

The scripts are **not executed by the Mac app**. Run them yourself in an elevated Windows PowerShell window after reviewing the changes. They are intentionally limited to a fresh SSH deployment: an existing `sshd_config`, running SSH service, account or share causes refusal. For an existing SSH server, integrate an equivalent dedicated-user `Match` block manually with your existing policy; do not replace the existing server configuration.

1. Use the Mac app's **Generate Mac key** action to create a dedicated Ed25519 identity, or select your own existing dedicated identity. The generated key has no passphrase and owner-only mode-0600 access; it is a bearer credential protected by the Mac account and disk encryption. An existing passphrase-protected key works when its matching key is already unlocked in the local SSH agent. The app never prompts for a private-key passphrase and never forwards the agent. Keep the private key on the Mac. The public key is the `.pub` file; only that public key goes to Windows. `IdentitiesOnly=yes` limits offers to the explicitly selected identity.
2. On Windows, review `Enable-DeskBridgeSFTP.ps1`. Supply the **client** public key, the Mac's exact LAN and/or Tailscale IP addresses, and the intended desktop user's SID. The wizard captures the original non-elevated user's SID before UAC, so alternate administrator credentials do not receive the share instead. This preview supports resolvable local Windows users, including Microsoft-account-linked local users; domain/Entra users need manual integration. Use a DHCP reservation if your LAN address changes.
3. Review mode is the default. To apply, for example:

```powershell
# First obtain this in the intended desktop user's NON-elevated PowerShell:
[Security.Principal.WindowsIdentity]::GetCurrent().User.Value
# Then supply that exact SID when applying from the elevated window:
.\Enable-DeskBridgeSFTP.ps1 -ClientPublicKey 'ssh-ed25519 AAAA... your-mac' -AllowedClientAddress '192.168.1.10','100.90.80.70' -DesktopUserSid 'S-1-5-21-111-222-333-1001' -Apply
```

The script installs the optional feature if needed, creates the `deskbridge-transfer` standard local account disabled with a random undisclosed password, and creates `C:\DeskBridgeShare\files`. The jail root is owned by Administrators and grants both the transfer account and selected desktop user read/execute only; the `files` child grants them Modify. Thus ordinary Explorer/editors can consume uploads and place downloads without elevating or changing the ACL. Setup metadata receives no additional desktop-user permission. The transfer account must never join Administrators. Global SSH policy permits only this user, public-key authentication, no shell/TTY, no forwarding and forced `internal-sftp` with `ChrootDirectory`. It disables the broad installer firewall rule and creates a rule for the supplied client IPs. Both syntax and effective-policy checks run before enabling the account or starting the service.

Protected template/recovery metadata are published as Prepared in `C:\ProgramData\DeskBridgeSFTP` before key generation and SSH validation. After an ordinary setup failure, fix the cause and repeat the same wizard action: Resume revalidates keys, syntax and effective restrictions before activating. Prepared metadata never authorizes a running deployment's Reuse shortcut. Earlier handled failures compensate only this invocation's new account (matching its actual SID) and empty directories; nonempty shared directories are retained for manual recovery. This is not crash-safe OS provisioning. Unknown pre-record interruptions, modified ownership/ACLs, a different desktop SID and older metadata require explicit manual review/migration rather than silent adoption. Changing share access through Explorer's Continue action changes the approved ACL and will correctly block managed Resume.

4. The script prints the **server** Ed25519 public key and its SHA256 fingerprint. Copy the public key to the Mac app through a channel you trust and compare its displayed fingerprint with Windows. A key obtained solely by scanning the network has not been authenticated. On a host-key change, stop and verify the new key independently; never turn off host verification.
5. Enter the Windows LAN/Tailscale address, port 22, username, private-key file and verified server public key in Knot. The remote share path is `/files`.

Uploads arrive in unique `/files/deskbridge-<UUID>/original-name` folders, preventing accidental replacement. The temporary upload is `.upload.part`, or `.upload-stage.part` if the original name equals `.upload.part` ignoring case. Both `.upload.part` and `.UPLOAD.PART` are valid original names and remain unchanged after completion. Downloads use an exclusive local temporary file and fail if the chosen final name exists. Interrupting an upload may leave one of those staging files inside that transfer's UUID folder; inspect and remove only that incomplete job manually. Do not replace it with a wildcard cleanup command.

To revoke access, review and run `Disable-DeskBridgeSFTP.ps1 -Apply`. It stops the dedicated service, disables the account, removes its firewall rule and archives its configuration. It retains your shared files, account, optional feature and host keys. Removing an authorized key stops future authentication; terminate established sessions when immediate revocation is required.

Resume, connection export and revocation verify protected recovery metadata/state, path ancestors, the transfer account's name and SID, the dedicated service executable and active configuration hash before service/account changes. Resume and export additionally require the recorded share ACLs, retained template and authorized key. Revocation does not open the mutable share or require a retained template/key: deleting shared files or changing share permissions cannot prevent revoking a verified deployment.

Before revocation stops the service, it holds process handles and verifies that every observed OpenSSH worker descends from that live service instance using native parent identity and creation times. An independent daemon using the same system binary is refused. A stopped service with remaining workers, a missing ancestor, or any ambiguous inventory requires manual recovery; retained PIDs or executable paths alone never authorize termination. Successful repeated revocation confirms that no workers remain and restores the recorded service startup policy. Worker termination uses those same captured handles; service control still uses the verified `sshd` service. Do not change the service, SSH configuration or firewall rules concurrently from another administrator session: service control is not an atomic PID compare-and-stop, and ambiguous or restarted state requires manual review. If startup fails, rollback may first disable the verified transfer account enabled during that attempt and remove a firewall rule created during that attempt; it still refuses to stop services or workers whose ownership cannot be proven. Changed account identity, service or active configuration requires manual review rather than stopping an unrelated deployment.

The EXE's revoke/uninstall operation also has a strictly read-only already-inactive outcome. It can succeed without adopting or deleting retained metadata only when the fixed `ProgramData\ssh\sshd_config` is absent, the exact `DeskBridge-SFTP-In-TCP` firewall rule is absent from configured/effective policy, the default-named `deskbridge-transfer` account is missing or disabled, `sshd` is missing or stopped, and no system OpenSSH server/session/auth worker is running. This lets helper removal finish after a prior revocation even if the disabled account or OpenSSH was later removed. No resources are changed in this path. Any active/unknown condition, inaccessible inventory or unknown worker path falls back to strict managed preflight or refusal; an existing configuration/rule cannot use this exception. Shared files and retained records stay untouched.

Resume/reuse and export also validate the complete dedicated firewall rule projection: one matching rule/filter set, enabled inbound TCP22 allow, expected profile/address/port/application/service/interface/security constraints and exact distinct client addresses. A matching name or address list alone is insufficient. Before reactivation replaces an existing named rule, it validates that complete projection against the rule's own prior address set, so an approved address change remains possible while an altered rule requires manual review. Failed reactivation removes only the new rule object returned during that attempt; an early validation or key-write failure does not delete a prior rule by name. This checks only the helper-owned rule; unrelated/GPO firewall policy is not adopted or overridden. `tests/Test-FirewallPolicy.ps1` exercises this pure validator with synthetic projections without reading or changing a machine's firewall.

Fresh setup validates an existing SSH directory before optional-feature operations. A newly created SSH directory receives its protected ACL at creation under Windows PowerShell 5.1; existing directory/key permissions are never repaired automatically. Both binaries are protected before execution, published configuration is checked before validation and activation, and the exported public host key plus its private key permissions are checked. After ownership and a stopped service are verified, failed reactivation restores the recorded startup policy before archiving its configuration. Unproven remaining workers interrupt that cleanup and require manual review; no inactivity success is reported.

Before exporting, select an address on the Wi-Fi/Ethernet or Tailscale interface that the Mac can reach. Virtual adapters and 169.254 link-local addresses may also appear; the first address is not a reachability test. Copy the Mac setup JSON to a local folder before UAC if it is on a mapped network drive. The dedicated transfer account may appear on the Windows sign-in screen; its random undisclosed password is not an interactive login credential.

The Mac's automatic client-address suggestions and Bonjour host candidates exclude APIPA and cap exported Mac suggestions at eight. Directly entered link-local addresses are retained only as an advanced exception for deliberately configured local links. Review all allowed Mac addresses before exporting; an omitted interface can be selected manually.

The Windows service must be updated through supported Windows/OpenSSH updates. Never add legacy `ssh-rsa` algorithms or weaken host checks to address a setup error. The Mac client deliberately accepts Ed25519 server pins only in this MVP.

Fixed ProgramData state/export paths remain fail-closed when a pre-existing object is untrusted, including local path squatting. The helper never reclaims or re-ACLs it. An administrator must inspect the object and retained data before any manual removal; an active or uncertain deployment still requires verified revocation/manual recovery. The already-inactive shortcut inspects the default-named account only and does not infer the status of custom manual deployments.

Uninstall always runs the broker's fixed-resource inventory; a missing `DeskBridgeSFTP` directory never proves inactivity. Missing/unknown recovery state or an unrelated active OpenSSH deployment may block removal and retain the helper. An administrator must review that state manually. This does not authorize taking over or stopping another SSH deployment.

Revocation must also pass a fresh inactivity inventory after its changes; denied firewall deletion, any remaining configured/effective `DeskBridge-SFTP-In-TCP` rule or an unknown same-named OpenSSH worker prevents the broker from attesting completion. It never stops workers outside the dedicated system OpenSSH path. The initial setup compiles its directory helper using private administrator-only CodeDOM temporary files and restores the process temporary-directory settings afterward.
